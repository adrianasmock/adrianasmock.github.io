Retail Sell-Through Dashboard

How is the brand selling at each retailer, and is growth coming from more stores or from each store selling more? This report answers that for a fictional snack brand across six retailers and 104 weeks of scan data.

Saltbrush Snack Co. is a fictional brand. Every number on this page comes from an invented dataset, not from an employer or client.

What the report answers

  • Retail $ and units, latest 52 weeks vs. year ago
  • Average item distribution (% of stores selling each item) and points gained
  • Velocity: $ per store, per SKU, per week, by product line
  • Promotion lift: base vs. promo velocity by retailer

What the sample data shows

Sales grew 26.3% vs. year ago. Average item distribution gained 8.8 points and velocity grew 10.0%, so growth came from both new stores and existing stores selling more. Promotions lifted velocity most at Summit Grocery (+92%) and least at Corner Convenience (+19%), which is where a trade conversation should start.

Data model

A star schema: one fact table with the numbers, and dimension tables for filtering. Relationships are one-to-many from each dimension to the fact table on its ID or key column.

TableContents
fact_retail_salesWeek × retailer × SKU: units, dollars, stores selling, total stores, promo flag
dim_weekWeek ending, year, month, fiscal week (1–104)
dim_productSKU, product, product line, flavor, list price, unit cost
dim_retailerRetailer, channel, total stores

Definitions & caveats

  • Average item distribution = stores selling ÷ total stores, summed over retailer × SKU × week rows. Over a period it is the average weekly share of each retailer's stores selling each item.
  • This is numeric distribution, not weighted ACV. Weighted ACV weights each store by its all-commodity sales volume and needs store-level ACV data, which this sample doesn't include. Brand-level distribution (stores selling any Saltbrush item) is higher: 69.1% vs. 68.0% for the average item.
  • Velocity = retail $ ÷ stores selling, summed over the same rows. Summing store counts across weeks is intentional: it turns them into store-weeks, so the result is $ per store selling, per item, per week.
  • Year-ago measures shift the selected window back 52 fiscal weeks, so they expect a period filter such as the latest 52 weeks.
  • Promo lift compares velocity in promoted vs. non-promoted weeks at the same retailer. It does not adjust for seasonality, so read it as directional.

This is a portfolio sample built on invented data. Before using measures like these in production, I validate them against source totals and agree the definitions with the business.

Key DAX measures

Retail $ = SUM ( fact_retail_sales[Dollars] )

-- Same 52-week window shifted back one year, using the fiscal week number
Retail $ YA =
VAR FirstWk = MIN ( dim_week[FiscalWeek] ) - 52
VAR LastWk  = MAX ( dim_week[FiscalWeek] ) - 52
RETURN
    CALCULATE (
        [Retail $],
        REMOVEFILTERS ( dim_week ),
        dim_week[FiscalWeek] >= FirstWk,
        dim_week[FiscalWeek] <= LastWk
    )

Retail $ % Chg YA = DIVIDE ( [Retail $] - [Retail $ YA], [Retail $ YA] )

-- Average item distribution: share of each retailer's stores selling each item.
-- Numeric distribution, not weighted ACV (no store-level all-commodity volume in this data).
-- Summed over weeks it becomes the average weekly share.
Avg Item Distribution % =
DIVIDE ( SUM ( fact_retail_sales[StoresSelling] ), SUM ( fact_retail_sales[TotalStores] ) )

Velocity $/Store/SKU/Wk =
DIVIDE ( [Retail $], SUM ( fact_retail_sales[StoresSelling] ) )

Promo Velocity =
DIVIDE (
    CALCULATE ( SUM ( fact_retail_sales[Units] ), fact_retail_sales[PromoFlag] = 1 ),
    CALCULATE ( SUM ( fact_retail_sales[StoresSelling] ), fact_retail_sales[PromoFlag] = 1 )
)

Base Velocity =
DIVIDE (
    CALCULATE ( SUM ( fact_retail_sales[Units] ), fact_retail_sales[PromoFlag] = 0 ),
    CALCULATE ( SUM ( fact_retail_sales[StoresSelling] ), fact_retail_sales[PromoFlag] = 0 )
)

Promo Lift % = DIVIDE ( [Promo Velocity], [Base Velocity] ) - 1
